# Правила Codex для репозитория «Почта леса»

1. Перед изменением исходников изучи `docs/00-index.md`, `docs/02-learning-methodology.md`, `docs/03-ux-flow.md`, `docs/04-screen-specifications.md`, `docs/05-design-system.md`, `docs/06-technical-architecture.md`, `docs/08-qa-and-analytics.md`. Источник заданий — `docs/data/lesson.v1.json`.
2. Нельзя самовольно менять образовательную цель: начальный твёрдый звук [м]. Не смешивать [м] с мягким [мʲ] и не утверждать обучение чтению слова за одно занятие. Порог 4/5 — демонстрационный, не диагноз.
3. Сохраняй последовательность: вступление → 2 baseline → 3 guided training → 5 assessment → reward → parent report. Не смешивай подсказки тренировки с самостоятельной оценкой.
4. Никаких меток с написанными словами на детских карточках: картинки + кнопки аудио. Для озвучки использовать манифест и честный fallback, не имитировать проверенное аудио.
5. Данные ребёнка не собираем. Нет удалённой аналитики, логина, оплаты, микрофона, геолокации. LocalStorage только для демо и без PII. Кнопка сброса обязательна.
6. Рабочая реализация: React, TypeScript, Vite. Не начинать с тяжёлых игровых движков и backend. Использовать уже подготовленные оригинальные SVG-ассеты; не копировать изображения Amaya.
7. Mobile-first 390×844, планшет 1024×768, центрированная демонстрация на desktop 1920×1080. На всех экранах все элементы должны быть видны/доступны, без горизонтального скролла.
8. Состояния ошибок, прерываний, возвратов, отсутствия аудио и помощи ребёнку — обязательны. Для QA предусмотреть детерминированный seed и тестовые сценарии.
9. Demo mode явно маркирован, отделён от реальных результатов и может открыть любой экран/состояние. Он не должен изменять нормальную аналитику.
10. Перед сдачей запускай typecheck, lint (если настроен), unit tests, build. Сверяй скриншоты с docs/wireframes и фиксируй расхождения. Для Pages `base: '/forest/'`.
11. Изменения вне текущей фазы — сначала объясни, не расширяй scope. Не объявляй педагогическую эффективность доказанной по игровому прохождению.
